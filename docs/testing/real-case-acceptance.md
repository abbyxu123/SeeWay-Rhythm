# 真实案例验收规程

日期：2026-08-21

真实个人案例用于验证完整流程和发现口径问题，不用于反向定义算法，也不代替固定金样。

## 前置条件

运行真实案例前，目标 Agent 必须已经：

1. 锁定适用的时间与流派口径。
2. 通过独立来源建立的固定金样。
3. 通过中间盘面事实、规则命中、冲突和边界测试。
4. 从 `unverified` 正式升级为 `available`。

未满足前置条件时，系统必须返回 `unsupported`。不能为了展示效果临时拼接结论。

## 所需输入

- 出生日期，并明确是公历还是农历；农历还要说明是否闰月。
- 出生时间及精度，例如精确到分钟、只确定时辰或时间未知。
- 出生地点，至少到可确定时区和经纬度的行政区。
- 出生时采用的时区；历史夏令时需要单独核对。
- 目标计算的日期、时间、地点和时区。
- 请求的模块或具体问题。
- 是否授权本次读取出生资料，以及是否允许保存结果。

姓名不是排盘验收的必要输入。测试记录使用不含姓名的案例 ID，公开仓库不得保存真实出生资料、原始语音或可识别个人的问事记录。

## 验收顺序

```text
确认输入历法、时间精度与授权
-> 运行固定金样并确认当前版本仍通过
-> 运行真实案例的历法与时间层
-> 展示适用计算核心的逐层中间事实
-> 展示规则命中、来源索引和冲突处理
-> 展示各 Agent 独立报告
-> 生成精简结论视图
-> 人工核盘并记录差异
```

逐层记录至少包含版本、输入摘要、计算事实、规则 ID、证据 ID、Agent 报告和中台关系。输入摘要应脱敏，审计日志只记录授权范围，不记录私密值。

## 判定规则

- 程序与金样不一致：先定位时间、口径、计算或规则层，不修改金样迎合程序。
- 真实案例与既有人工盘不一致：保留双方完整中间结果，先确认双方采用的流派和时间口径。
- 现实经历与结论不一致：可以作为研究备注，不能据此单例修改确定性规则。
- 规则证据互相抵消：返回 `mixed` 或 `insufficient`，不强行选择吉凶。
- 缺少会改变盘面的输入：返回 `needs_input`，一次只追问一项。
- 计算器尚未验收：返回 `unsupported`，不生成建议。
