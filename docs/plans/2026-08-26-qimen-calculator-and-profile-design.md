# 奇门计算器与用户档案设计

日期：2026-08-26

状态：已确认，进入逐层实施

## 1. 目标

第一版先完成一条可复现、可校验、不会编造的硬件链路：用户建立出生档案，设备按当前或所选时辰生成张志春时家转盘拆补奇门盘，只有盘面通过独立校验后，才显示“有利、注意、方位、建议”；按键可以查看同一盘面的九宫事实。

V1 的“准确”指时间、局数、九宫事实、规则命中、来源和版本可以重复计算并人工核对，不把传统术数表述成经现代科学验证的预测。

## 2. 两种时间严格分开

系统同时保存两类时间，禁止混用：

1. `profile.birthTime`：用户出生年月日时辰、时区、地点和精度，用于个人档案以及后续有明确来源的年命或个人化规则。
2. `targetTime`：当前时刻、下一时辰或用户选择的日期时间，用于生成正在显示的时家奇门盘。

当前奇门盘由 `targetTime` 决定。出生资料不能修改阴阳遁、三元、局数、星门神或天地盘事实。尚未实现个人化规则时，出生档案可以已保存，但屏幕必须诚实标明当前结果是“时辰通用盘”，不能假装已经个性化。

## 3. 确定性计算链路

```text
公历时间 + IANA 时区
-> time-core：民用时间、节气、四柱、时辰
-> qimen-core：阴阳遁、三元、局数
-> qimen-core：地盘、旬首、空亡、马星
-> qimen-core：值符、值使、天盘、九星、八门、八神
-> independent verifier：逐项重算与结构不变量
-> qimen-guidance：有利、注意、方位、建议及规则证据
-> device contract：适配 400x300 屏幕
-> firmware：缓存、按键和显示
```

每一层只消费上一层已经验证的事实。语言模型不参与排盘；解释层也不能修改任何盘面字段。

## 4. 计算器分层

### 4.1 阴阳遁、三元与局数

- 以 `time-core` 的当前节气和日柱为输入。
- 夏至至冬至前采用阴遁，冬至至夏至前采用阳遁。
- 采用拆补法的符头与上中下元分组。
- 按已锁定的二十四节气三元局数表确定局数。
- 节气交接以 `time-core` 的精确交节时刻为边界，不按公历日期猜测。

### 4.2 地盘与旬首事实

- 三奇六仪按阳顺阴逆布九宫。
- 由时柱六十甲子索引确定旬首及其所遁六仪。
- 计算空亡宫与驿马宫，保留完整中间事实供校验。

### 4.3 值符值使与星门神

- 先确定值符星、值使门的原始宫和目标宫。
- 再分别排天盘、九星、八门和八神。
- 中五宫寄宫规则固定在算法版本中，不由展示层临时判断。

### 4.4 独立校验器

校验器不能调用计算器的总编排函数。它使用独立推导和不可变规则表检查阴阳遁、局数、地盘顺逆、旬首、值符值使位置、九宫词表唯一性和黄金案例逐宫一致性。任何一项失败，状态为 `blocked` 或 `unverified`，不产生四类建议。

## 5. 用户档案

首版档案字段：

- `profileId` 与递增 `profileVersion`。
- 出生公历时间、IANA 时区、地点文本和输入精度。
- 姓名或昵称可选；姓名不参与排盘。
- 性别可选，只有某个已实现体系明确需要时才读取。
- 原始输入与标准化时间同时保存，修改资料生成新版本。

当前非触屏设备不承担复杂文字输入。V1 先通过本地配置工具或同一局域网设置页写入档案，设备只负责确认、选择档案和显示。以后 iOS、iPadOS 或小程序继续使用同一档案契约。

## 6. 屏幕行为

默认页保持当前设计：顶部显示时间、星期、公历、农历、节气和四柱；主体显示当前时辰及“有利、注意、方位、建议”。

- 未设置档案：显示“请设置用户档案”，但仍可显示通用时间信息。
- 档案已设置、计算器未通过：显示“等待算法验证”，不填充占断文案。
- 盘面已验证、规则层未通过：允许查看九宫事实，不显示四类结论。
- 全链路通过：显示四类结论，每条保留规则 ID 和盘面证据供展开。
- KEY 短按：当前时辰与下一时辰切换。
- BOOT 短按：摘要页与九宫事实页切换。

## 7. 错误与边界

- 无效日期、时区或节气上下文：停止计算并显示明确错误。
- 恰逢节气交接：使用精确瞬间归属，并把边界标记传给校验器。
- 出生时间只有时辰范围：保存相应精度，不伪造分钟。
- 当前时间与出生时间字段混淆：契约解析失败。
- 设备离线：只显示带计算版本和更新时间的最后一个已验证缓存。
- 规则或来源未锁定：返回 `unsupported`，禁止通用幸运文案兜底。

## 8. 测试与验收

每层都按 RED-GREEN-REFACTOR 实现：

- 单元测试覆盖每个二十四节气的上中下元局数、阴阳遁边界和六十日符头分组。
- 三个来源黄金案例必须从输入时间完整计算到逐宫一致，不能直接加载期望盘作为结果。
- 增加夏至、冬至交接前后一秒等边界案例。
- 校验器测试必须证明修改任一局数、地盘干、星、门或神会被拒绝。
- 出生档案测试必须证明修改生日不会改变同一 `targetTime` 的基础奇门盘。
- 硬件验收使用已提供的测试档案：男，1997-06-19 05:30，安徽泾县，`Asia/Shanghai`；它用于端到端数据流测试，不用于迁就或修改算法期望。

## 9. 阶段顺序

1. 阴阳遁、三元、局数。
2. 地盘、旬首、空亡、马星。
3. 值符值使、天盘、九星、八门、八神。
4. 独立校验与 Agent availability 总门。
5. 用户出生档案与本地设置入口。
6. 四类规则与证据输出。
7. 设备契约、烧录和真实档案端到端验收。

每个阶段独立提交、推送和汇报；上一阶段未经审核，不进入下一阶段。
