# SeeWay Rhythm 多智能体推演平台设计

日期：2026-08-21

状态：产品与架构方向已确认，进入实施规划

## 1. 设计目标

SeeWay Rhythm 要把多个传统术数体系做成彼此独立、可组合、可核验的 Agent。每个 Agent 必须拥有自己的输入要求、确定性计算、规则库、推理过程、结论和记忆边界；总控系统只负责理解用户目标、分发任务、保护上下文和组织结果，不把各体系强行压成一个模糊总分。

第一版继续以个人研究和实际使用为目标：奇门主导每个时辰的常显提示和专题问事，紫微提供人生阶段与日历背景，八字作为可选择的个人底层资料，奇门金融承担独立的研究型金融场景。梅花易数作为后续按需补充。

“准确”在本项目中指：时间数据、排盘事实、规则执行、版本记录和证据链可以复现并人工核对。术数结论属于传统文化模型和个人研究输出，不代表经现代科学验证的现实预测。

## 2. 架构选择

采用“隔离领域 Agent + 可信推演中台 + 命名空间记忆”。

没有采用所有 Agent 共享一个大上下文的方案，因为这会造成术语、规则和用户记录互相污染。也不在第一版引入企业级微服务或事件总线，因为单用户、本地优先阶段不需要这类部署复杂度。

内部架构名称：**可信推演中台**。

面向产品的能力名称：**规则可追溯的多体系协同引擎**，英文可使用 `Rule-Traceable Multi-System Engine`。

它应能诚实支持以下说明：

- 每个体系独立计算和作出结论。
- 结论能够回溯到盘面条件、来源规则和版本。
- 多体系意见冲突时保留分歧，不伪造一致。
- 出生资料、问事记录和用户记忆默认本地保存且可控。

## 3. 七个 Agent

### 3.1 总控 Agent（Orchestrator）

职责：

- 判断问题属于时辰节律、专题问事、人生阶段、个人背景、金融研究或其他领域。
- 检查是否缺少会改变计算结果的时间、地点、对象或目标。
- 选择一个主 Agent 和零至多个辅助 Agent。
- 组织结果，明确标注来源与冲突。
- 在读取或写入长期记忆前执行授权检查。

总控 Agent 不排盘，不直接制造吉凶结论，也不能替代领域 Agent 修改结论。

### 3.2 奇门时辰 Agent（Qimen Rhythm）

面向常显设备和日历时间轴，计算当前及下一时辰。输出各事项的顺势点、谨慎点、有利与回避方向、行动建议和证据一致程度。

### 3.3 奇门问事 Agent（Qimen Query）

面向具体问题，支持关系、事业、学习、合作、沟通、出行、择时与方位等类别。它根据问题类别选择用神，并在关键信息不足时一次只追问一个问题。

### 3.4 紫微时间轴 Agent（Ziwei Timeline）

负责本命、大限、流年，以及只有在来源与金样得到确认后才启用的流月层。紫微主要解释中长期背景，不为了迎合两小时界面而强行生成时辰级结论。

### 3.5 八字背景 Agent（Bazi Profile）

负责四柱、五行、十神、格局、大运与流年背景。它默认是可选辅助层；总控在确有价值时询问用户是否加入，而不是对每个问题自动读取。

### 3.6 奇门金融 Agent（Qimen Finance）

复用同一套 `qimen-core` 盘面事实，并结合经过来源整理的金融专题规则、市场指标和用户授权的交易记录形成独立研究结论。首版不连接券商、不保存券商凭证、不自动交易，也不输出收益保证或无条件买卖指令。

### 3.7 梅花易数 Agent（Meihua）

作为后续按需启用的补充体系。只有在起卦输入、规则口径和人工金样完成后才进入生产流程；在此之前只登记能力，不返回伪造结果。

三个奇门 Agent 共享 `qimen-core`，但各自拥有不同的领域规则、输入要求、记忆范围和表达模板。

## 4. Agent 的判断权限

每个领域 Agent 包含五部分：

1. 计算器：生成不可由语言模型修改的盘面事实。
2. 规则库：记录来源、适用流派、条件、强度和冲突优先级。
3. 推理层：允许规则推理与受约束的语言模型参与解释和权重判断。
4. 结论层：独立给出有利、不利、方向、建议和不确定性。
5. 证据层：记录命中的盘面条件、规则编号、来源位置和版本。

最终原则是：**Agent 可以自己作判断，但不能凭空作判断。**

语言模型可以：

- 识别问题范围与缺失输入。
- 在领域规则允许的范围内解释、比较和组织证据。
- 对相互冲突的规则给出带理由的权重判断。
- 把完整分析压缩成适合屏幕或语音的表达。

语言模型不可以：

- 修改干支、宫位、星、门、神、十神等已计算事实。
- 引用不存在的规则或来源。
- 把证据不足表达成确定吉凶。
- 隐藏不同 Agent 之间的重要冲突。

## 5. 可信推演中台

中台不是第八个自由发挥的术数 Agent，而是一组确定性的控制组件。

### 5.1 五道关口

1. 输入关：确定范围，检查时间、地点、人物关系与目标是否完整。
2. 上下文关：只向 Agent 提供完成任务所需的最少数据。
3. 计算关：校验盘面结构、规则版本和 Agent 输出契约。
4. 结果关：检查证据链、冲突、数据时效、风险措辞和展示长度。
5. 记忆关：只有在用户明确选择后，才永久保存本次问题或结果。

### 5.2 核心组件

- Agent Registry：登记能力、版本、输入、输出和允许读取的记忆域。
- Router：按用户明确选择、领域匹配、时间粒度和输入完整度选取 Agent。
- Context Broker：生成最小化、脱敏且已授权的上下文。
- Contract Validator：拒绝缺字段、无证据、版本不兼容或越权的结果。
- Conflict Inspector：保留各 Agent 原始意见并标记一致、补充或冲突。
- Synthesis Presenter：由主 Agent 结论领衔，辅助 Agent 只提供背景与修正。
- Memory Gate：处理仅本次、保存时间轴、收藏、备注、导出和删除。
- Audit Log：记录输入摘要、调用路径、版本、证据和错误，不默认记录原始语音。
- Entitlement and Notification：管理可查看时间范围和提醒能力，不参与术数计算。

## 6. 路由与权重

路由按以下顺序执行：

1. 用户明确指定的体系或模块优先。
2. 问题领域匹配决定主 Agent。
3. 所需时间粒度决定可用 Agent。
4. 缺少必需输入的 Agent 不执行，先追问或降级。
5. 来源未验证、规则未实现或金样未通过的能力不得进入正式结论。

系统不把所有体系合并成一个总吉凶分。主 Agent 拥有主结论，辅助 Agent 只能提供背景、增强、削弱或冲突提示；界面始终能展开查看每个 Agent 的独立输出。

金融问事示例：

```text
用户提出金融问题
-> 总控识别标的、周期和目标
-> 奇门金融 Agent 成为主 Agent
-> 询问是否加入八字或紫微背景
-> 上下文关读取已授权的金融档案
-> 各 Agent 独立计算
-> 结果关检查证据与风险措辞
-> 总控保留分歧并形成展示结果
-> 用户决定是否保存、收藏或加入提醒
```

## 7. 输入输出契约

每次调用至少包含：

```ts
interface AgentRequest {
  requestId: string;
  intent: string;
  category: string;
  questionTime: string;
  targetTime?: string;
  timezone: string;
  location?: string;
  actors?: Array<{ role: string; relation?: string }>;
  profileScopes: string[];
  memoryScopes: string[];
  requestedAgent?: string;
}
```

每个 Agent 返回独立报告：

```ts
interface AgentReport {
  agentId: string;
  agentVersion: string;
  status: "complete" | "needs_input" | "unsupported" | "error";
  conclusion?: {
    favorable: string[];
    cautions: string[];
    supportiveDirection?: string;
    avoidDirection?: string;
    action: string;
    tendency: "favorable" | "caution" | "mixed" | "insufficient";
  };
  chartSnapshotId?: string;
  evidence: EvidenceRef[];
  conflicts: ConflictRef[];
  requiredInputs: string[];
  ruleVersion: string;
  generatedAt: string;
}
```

`complete` 结果必须有证据；未实现能力必须明确返回 `unsupported`，不能用通用文案填空。

## 8. 记忆与隐私

记忆分为四类：

- 身份档案：出生时间、出生地点、时区和常用地点。
- 领域记忆：金融、事业、关系等彼此隔离的命名空间。
- 时间线记录：问题、当时结论、后续实际情况和用户备注。
- 使用偏好：提醒类别、展示方式、通知范围和默认辅助 Agent。

每个结果提供四个明确动作：仅本次、不保存；保存到时间轴；收藏；添加备注。保存的快照包含原始输入摘要、盘面快照、各 Agent 报告、规则版本和 Agent 版本，防止规则升级后历史记录被静默改写。

用户可以导出和删除全部资料。第一版本地优先；后续加入静态加密与跨设备同步时，再单独设计密钥和恢复流程。

金融记忆可以保存市场、观察列表、持有周期偏好、常用指标、手工交易理由和结果、用户自定风险限制。原始记录与系统推断必须分开存放。首版不保存券商账号、密钥或自动交易授权。

## 9. 日历与时间轴

日历是常显页之外的第二主界面：

- 月视图支持左右滑动和选择日期。
- 日视图展开十二个时辰。
- 每个时辰可显示奇门倾向、紫微阶段背景、可选八字叠加、提醒、收藏和事后备注。
- 每一条标记都显示来源 Agent。
- 推荐标签为“值得把握”“需要谨慎”“冲突明显”“暂无显著倾向”。

只有来源中存在明确定义、程序已实现且金样通过的强规则，才能显示相应的强警示名称。不能为了吸引注意而编造“极阴极煞”等标签。

时辰级标记主要来自奇门。紫微只有在来源支持且动态层通过验证时，才产生对应日期或时辰标记；否则只作为阶段背景。

设备和 iOS 本地通知按确定的日期时间排程。建议免费版提供滚动未来 30 天，Pro 提供一年、完整历史和高级提醒。更远年份按需计算，不预生成“所有未来”。一次性 Pro 适合本地确定性能力；订阅只用于持续产生成本和价值的市场数据、云同步、云语音或持续规则更新。

## 10. 金融模块边界

奇门金融 Agent 的规则研究可参考本地《奇门应用研究与股市实战解秘》及经核验的技术指标资料。规则实现必须区分：

- 客观市场输入，例如价格、成交量和指标值。
- 术数盘面事实。
- 来源规则的匹配结果。
- Agent 的解释与权重。
- 用户最终决定和事后记录。

公开版本将其定位为文化体验与个人研究辅助，不替代持牌金融意见。所有涉及实时行情的判断必须标记数据来源和时间；数据过期时不生成实时倾向。Apple 平台上的数字功能解锁遵循应用内购买要求，订阅必须提供持续价值，具体上线方案在 V2 实施前再次核对当时的审核规则。

## 11. 错误与降级

- 时间或时区无效：停止排盘，要求纠正，不猜测。
- 出生时辰不确定：明确记录精度，不启用依赖该字段的个人化规则。
- Agent 缺少规则或金样：返回 `unsupported`。
- 规则冲突无法裁决：保留证据并返回 `mixed`。
- 辅助 Agent 失败：主 Agent 可继续，但界面标明缺失的背景层。
- 记忆未授权：只使用本次输入，任务结束后不持久化。
- 市场数据过期：停止实时金融判断，允许查看历史研究结果。
- 设备断网：显示带更新时间的最后有效缓存。

## 12. 测试与验收

### 12.1 自动测试

- 时间边界：十二时辰边界、子时换日、节气交接、时区和夏令时。
- 排盘金样：对每一层中间结果逐项核对，不只比较最终短句。
- 规则测试：每条规则包含命中、不命中、边界和冲突案例。
- Agent 契约：缺失证据、越权读取、无版本和虚构能力必须失败。
- 路由测试：金融、时辰、问事、紫微时间轴和可选八字叠加。
- 记忆测试：拒绝未授权读取、跨命名空间污染和静默持久化。
- 可复现测试：相同输入、数据和版本必须得到相同报告。
- 设备与通知：断网、重启、缓存损坏、RTC 偏差和时辰切换。

### 12.2 人工验收

1. 先使用来源明确且人工核对过的固定案例建立金样。
2. 程序完整通过排盘、规则、Agent、中台和展示链路。
3. 用户提供一个真实年月日、出生时辰、出生地和目标时间。
4. 以该资料完成一次端到端运行，展示每层计算事实、命中规则、独立 Agent 结论、冲突和最终摘要。
5. 人工对照资料或既有排盘，记录差异并修正实现；不能为了让案例“看起来准”而修改期望结果。

## 13. 分阶段交付

### 阶段 A：可信底座

建立 TypeScript 工作区、Agent 契约、注册表、五道关口、隔离记忆接口、路由和审计测试。所有术数 Agent 初始返回 `unsupported`，不提供占位吉凶。

### 阶段 B：时间与奇门核心

确认时间口径和流派规则，建立人工金样，逐层实现 `time-core` 与 `qimen-core`。先接入奇门时辰 Agent，再接入奇门问事 Agent。

### 阶段 C：时间轴与个人背景

实现紫微、八字的已验证层，接入日历、历史快照和提醒。

### 阶段 D：金融研究 Agent

建立金融规则索引、历史数据适配、用户金融记忆和风险检查。先做回看与研究，不做自动交易。

### 阶段 E：设备与消费端

完成本地控制台、ESP32 常显与语音终端，再以同一合同开发 iPhone 和 iPad 版本。

## 14. 实施前必须确认的规则口径

- 出生盘与问事盘使用民用时、真太阳时还是可配置双口径。
- 子时换日与早晚子时规则。
- 节气边界的数据源和精度。
- 阴阳遁、局数和转盘排布的主版本。
- 年命、日干、时干与专题用神的优先级。
- 紫微第一版启用到本命、流年还是经验证的流月。
- 八字加入主结论时的权重与冲突表达。

这些口径必须先写入版本化规则文档，再进入可执行代码。
