# SeeWay Rhythm 时间与奇门核心设计

日期：2026-08-21

状态：已确认，进入实施

## 1. 目标

第一阶段实现可复现、可核对的历法事实与奇门盘面事实。系统接收一个带所在地时区的民用时间，输出该时刻所属时辰、干支、节气、阴阳遁、局数以及完整九宫排布。

本阶段不直接生成“吉”“凶”“宜出行”等解释性结论。判断规则必须在基础盘经过人工金样核对后独立接入，避免把历法错误、排盘错误和解释错误混在一起。

## 2. 主体系与版本

首版只采用一套主体系：

- 时家奇门。
- 转盘法。
- 拆补法定局。
- 以张志春教材与课程材料作为主要规则来源。
- 飞盘、置闰等替代口径不混入首版；未来只能以新的算法版本独立实现。

首版约定版本标识：

- 时间口径：`time-cn-zhang-v1`
- 奇门排盘：`qimen-zhuanpan-chaibu-v1`

版本标识必须进入每一次计算结果和后续证据链。

## 3. 三层边界

### 3.1 输入时间层

保存用户输入的本地日期时间、IANA 时区、输入精度和地点信息。默认时区为 `Asia/Shanghai`，但不得用固定 UTC+8 字符串替代时区字段。

首版当前时辰盘采用所在地民用钟表时间。真太阳时保留为后续可切换研究口径，不覆盖原始输入，也不在首版默认启用。

### 3.2 历法事实层 `time-core`

`time-core` 负责：

- 输入校验和时区归一化。
- 公历、农历和干支事实。
- 精确节气时刻与交节归属。
- 两小时时辰范围。
- 子时和日期边界的版本化处理。
- 为奇门计算提供不可变的结构化时间上下文。

历法依赖首选 `tyme4ts`。它只作为历法事实来源，不直接提供本项目的奇门吉凶结论。项目必须用固定案例和边界案例校验依赖输出，不能把第三方库视为免检真值。

### 3.3 奇门事实层 `qimen-core`

`qimen-core` 只消费经过验证的时间上下文，负责：

- 阴遁与阳遁。
- 上、中、下元与拆补定局。
- 地盘三奇六仪。
- 旬首、值符和值使。
- 天盘、九星、八门和八神。
- 空亡与马星。
- 完整九宫盘面事实。

它不得访问用户情绪、历史记忆或语言模型，也不得输出未经规则层支持的行动建议。

## 4. 数据流

```text
本地日期时间 + IANA 时区 + 地点
-> 输入校验
-> time-core 历法事实
-> qimen-core 奇门盘面事实
-> 金样比对和证据记录
-> 后续判断规则层
-> Agent
-> 设备精简展示
```

任何一层失败都返回明确错误，不允许用当前系统时间、默认地点或猜测值静默补齐。

## 5. 核心输出

时间上下文至少包括：

- 原始本地日期时间和时区。
- 对应 UTC 时刻。
- 公历和农历日期。
- 年、月、日、时干支。
- 当前节气、前后节气及精确交节时刻。
- 时辰地支、开始和结束时刻。
- 时间口径版本。

奇门盘至少包括：

- 阴遁或阳遁、局数、三元。
- 旬首、值符、值使。
- 九宫编号、宫名、五行和方位。
- 每宫地盘干、天盘干、星、门、神。
- 空亡宫和马星宫。
- 奇门算法版本和来源索引。

所有输出为不可变结构，并通过运行时 schema 校验。

## 6. 错误与边界

以下情况停止排盘并返回结构化错误：

- 日期、时间或 IANA 时区无效。
- 时间精度不足以判定时辰。
- 输入恰逢边界但口径版本缺失。
- 历法依赖输出缺项或与金样冲突。
- 尚未验证的排盘分支被请求。

节气交接、23:00 子时、00:00 民用日期切换和闰月必须有独立边界测试。边界归属由版本化规则决定，不散落在界面或 Agent 中。

## 7. 验证策略

测试分为四层：

1. 映射测试：天干、地支、九宫、方位、星门神等固定表。
2. 时间测试：普通时刻、时辰切换、子时、节气精确交接和时区。
3. 排盘金样：逐项比较阴阳遁、局数、值符值使和九宫内容，不只比较最终文字。
4. 纵向测试：时间输入经过 `time-core` 和 `qimen-core` 后形成可供 Agent 消费的结构化盘面。

每个生产分支至少需要一个正常金样和一个边界金样。人工核盘记录必须包含来源、核对人、核对日期和差异说明。不能为了让案例通过而反向修改期望结果。

## 8. 实施顺序

1. 建立 `time-core` 的契约和边界测试。
2. 接入并封装历法依赖，锁定时间上下文。
3. 建立奇门金样文件格式和验证器。
4. 从固定映射、阴阳遁和局数开始实现 `qimen-core`。
5. 逐层加入地盘、旬首、值符值使、天盘、星、门、神、空亡和马星。
6. 完成金样后再启用 `qimen-rhythm` Agent。

## 9. 完成标准

只有同时满足以下条件，奇门时辰 Agent 才能从 `unverified` 改为 `available`：

- 相同输入在同一算法版本下得到完全相同的盘面。
- 正常盘和全部边界金样逐宫一致。
- 所有中间事实均可追溯到规则编号和来源。
- 完整测试、类型检查和纵向测试通过。
- 未验证分支仍然明确拒绝执行。
