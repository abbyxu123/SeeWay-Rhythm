# 可信推演中台

日期：2026-08-21

本文描述仓库当前已经实现的多 Agent 可信底座。它不包含奇门、紫微、八字或梅花的排盘计算器，也不产生占位吉凶文案。

## Agent 登记表

| Agent | 职责 | 计算核心 | 当前状态 |
| --- | --- | --- | --- |
| `orchestrator` | 校验、路由、授权、组织结果 | 无 | `available` |
| `qimen-rhythm` | 当前及下一时辰节律 | `qimen-core` | `unverified` |
| `qimen-query` | 具体事项问事 | `qimen-core` | `unverified` |
| `ziwei-timeline` | 本命与中长期时间轴 | `ziwei-core` | `unverified` |
| `bazi-profile` | 四柱与个人背景 | `bazi-core` | `unverified` |
| `qimen-finance` | 金融研究场景 | `qimen-core` | `unverified` |
| `meihua` | 按需起卦问事 | `meihua-core` | `unverified` |

`unverified` 不是“精度较低”，而是该计算器尚未通过规则口径、金样和边界测试。对应适配器只能返回 `unsupported`，不得返回有利、不利、方向或建议。

## 已实现的执行顺序

```text
严格校验请求
-> 确定一个主 Agent 和可选辅助 Agent
-> 缺少关键信息时只追问第一项
-> 按 Agent 声明和用户授权求最小上下文交集
-> 执行主 Agent
-> 只执行用户明确启用且当前可用的辅助 Agent
-> 核验执行器身份、可信定义、超时和报告契约
-> 核验每条结论引用的证据确实属于该报告
-> 保留一致、修正、冲突或不可用关系
-> 对结果包含的全部 Agent 校验是否允许持久化
-> 返回不含私密值的审计元数据
```

中台不会排盘、修改领域 Agent 的结论，也不会把多个体系压成一个总吉凶分。测试用的假 Agent 只存在于测试文件中，用来证明冲突报告能够完整通过链路。

## 路由示例

当前时辰请求以 `qimen-rhythm` 为主。具体问事以 `qimen-query` 为主。紫微时间轴、八字背景、奇门金融和梅花请求分别进入自己的 Agent。

金融请求必须先有标的和投资周期。缺少两者时，中台先询问标的；补齐后才询问周期。八字和紫微只作为可选建议，未经用户启用不会执行，也不会读取出生资料。

显式指定 Agent 只有在该 Agent 支持当前事项类别时才生效，不能借此绕过能力边界。

路由结果在运行时再次通过严格契约校验并复制后才冻结。中台还会重新核对正式路由得出的主 Agent、必需输入、用户选中的辅助 Agent、状态和权限；替换实现不能静默省略金融标的、选择不兼容 Agent、伪造可用状态或借用调用方对象作为可变权威。生产入口固定使用正式注册表与正式路由，状态覆盖只存在于带运行时环境限制的测试工厂中。

## 上下文与记忆授权

请求中的 `profileScopes` 和 `memoryScopes` 是本次授权范围，不是私密数据本身。每个 Agent 只能得到以下两者的交集：

1. 用户本次明确授权的范围。
2. Agent 注册表声明允许读取的范围。

例如，`qimen-finance` 可以声明请求 `finance` 记忆，但用户没有授权时，中台返回拒绝范围而不会提供数据。`qimen-rhythm` 即使收到包含金融记忆的请求，也无权扩大自己的权限。

传给 Agent 的请求也按授权结果重新投影：地点只在该 Agent 获准 `current-location` 时出现，辅助 Agent 不接收原始人物列表或原始问题文本，金融标的和周期只传给金融主 Agent。执行器自报的定义必须与可信注册表一致，返回报告的 Agent ID 也必须与实际被调用者一致。

当前版本只实现授权决策和审计中的范围名称，尚未实现数据库、文件读取或真实 Context Broker。审计记录包含请求 ID、执行过的 Agent、获准范围和注入时钟生成的时间，不记录出生资料、地点值、原始问题或原始语音。

持久化必须由用户选择：

- `once`：不产生写操作。
- `save_timeline`：需要本次授权 `timeline`。
- `bookmark`：需要本次授权 `timeline`。
- `add_note`：需要本次授权 `timeline`。

组合结果的持久化会逐个检查所有已执行 Agent。任意一层无权写入时，整份组合结果不产生写操作。

## 证据与故障边界

完整结论不是字符串列表。每一条顺势事项、谨慎事项、方向、行动建议和总体倾向都是独立声明或带有专门引用，并携带至少一个 `evidenceId`。Agent 间关系只引用支撑各自总体倾向的证据，不会把报告中的无关背景证据全部归到冲突上。契约会拒绝以下报告：

- 声明引用了报告中不存在的证据。
- 冲突引用了报告中不存在的证据。
- 不同报告复用了同一个证据 ID。
- 未验证 Agent 返回了 `complete` 结论。
- 执行器返回了另一个 Agent 的身份。

Agent 抛错、超时或返回畸形报告，会在边界内转换为统一、脱敏的 `error` 报告。主 Agent 失败时仍返回可审计错误；辅助 Agent 失败时保留有效主报告，并把该辅助关系标为不可用。原始异常消息不会进入用户结果或审计元数据。

总控为每次执行提供 `AbortSignal`，超时时先发出取消信号再返回错误。内置计算器必须协作响应取消；未来若允许不可信第三方实现，应改在可强制终止的 Worker 或独立进程中运行。

## 结果状态

- `unsupported`：能力或计算器尚未验证。报告没有结论和证据，只说明稳定原因码与启用前置条件。
- `needs_input`：能力存在，但当前请求缺少会改变计算结果的字段；中台一次只要求一个字段。
- `complete` + `insufficient`：计算和规则链已完整执行，也有可追溯证据，但证据不足以支持明确的有利或谨慎倾向。
- `error`：执行异常、超时或外部依赖失败，不得伪装成术数结论；对外消息不包含内部异常详情。

因此，`unsupported` 与 `insufficient` 不能互换：前者没有资格计算，后者完成了计算但没有足够方向性证据。

## 从 `unverified` 升为 `available`

一个领域 Agent 只有同时具备以下证据，才能修改注册表状态：

1. 相关时间、历法和流派口径已在版本化文档中锁定。
2. 确定性计算器已经实现，相同输入和版本得到相同中间事实。
3. 金样期望来自人工核盘或独立可信来源，不由被测程序反向生成。
4. 金样逐层核对时间、干支、局数、宫位、星门神仪、用神和规则命中等适用字段。
5. 规则具有稳定 ID、版本、来源索引、适用条件和冲突优先级。
6. 契约、边界、越权、冲突和失败降级测试全部通过。
7. 代码审查确认报告不含虚构证据，版本与状态变更一同提交。

启用一个 Agent 不会自动启用共享同一计算核心的其他 Agent。每个 Agent 的领域规则和金样必须单独验收。
